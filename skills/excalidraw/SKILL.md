# Excalidraw 白板

## 这个画板是共享的

**用户在同一个画板上和你同时作画。** 你写入的瞬间会替换该场景的全部图元——如果你不先读，就等于抹掉他刚画的东西。

所以任何修改都走这三步，**没有例外**：

1. `board_get` 读当前场景，拿到 `rev` 和完整的 `elements`
2. 在你读到的 `elements` 基础上改（保留所有原有元素的 `id` 不变，只动你要动的）
3. `board_write`，把 `baseRev` 设成第 1 步读到的 `rev`

第 3 步如果提示冲突，说明你读之后有人改过。**不要覆盖**，重新 `board_get` 再改一次。

完全从头画一张新图时，第 1 步仍然要做——那块画板上可能已经有用户的东西。

## 什么时候画，什么时候不画

画：三个以上部件交互、多步流程、有分支决策、要对比两种方案、用户明确说"画""图""可视化"。

不画：能用两三行列表说清楚的；用户只是闲聊；需要严格 UML 或正式图表规范的场合。

## 只能用六种图元

`rectangle` `ellipse` `diamond` `arrow` `line` `text`

**不要用** `image`（需要二进制 files）、`frame`、`embeddable`、`iframe`、`freedraw`。

## 元素格式（紧凑版）

工具读写的是**紧凑格式**，不是你导出时看到的完整 Excalidraw JSON。完整格式有 26 个字段、大半是配色和元数据，模型没必要碰，后端会补全。

**必填**：`id` `t` `x` `y` `w` `h`

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一标识。**改已有元素时沿用原 id** |
| `t` | 类型：rectangle / ellipse / diamond / arrow / line / text |
| `x` `y` | 左上角坐标，**用 .5 结尾**（如 `425.5`） |
| `w` `h` | 宽高 |
| `label` | **写在形状里的文字**。写了它，双击形状就能改字，拖动形状字也跟着走。**箭头也能写，它会长在线上** |
| `s` | 描边色，如 `#1e40af` |
| `bg` | 填充色，如 `#dbeafe` |
| `lc` | label 文字颜色，默认 `#334155` |
| `lfs` | label 字号。形状内默认 20，**箭头上默认 16** |
| `text` | **仅独立 text 元素**（浮在形状外的说明、标题） |
| `fs` | 字号，默认 20 |
| `from` | **仅 arrow/line**：起点绑定的元素 id |
| `to` | **仅 arrow/line**：终点绑定的元素 id |
| `dash` | `"dashed"` 表示返回 / 异步 / 回环 |
| `op` | 透明度 0–100 |
| `clean` | `true` 表示干净直线（技术图默认加这个） |

**不需要写** `seed`、`index`、`version`——后端给新元素生成，为同 id 的旧元素保留原值。

**强烈建议用 `label` 和 `from`/`to`**，而不是给每个框配一个独立 text 再手画坐标：
- 形状的 `label` 生成的是**真绑定文字**，双击形状就能编辑，拖形状时文字不脱节；
- **箭头也可以写 `label`**（比如 `"label": "是"`），它会长在线上并跟着线走。分支上的「是」「否」必须这么写；
- `from`/`to` 生成的是**真绑定箭头**，拖动节点时箭头端点自动跟随，不用你重算坐标。

只有标题、图例、游离注释才用独立的 `text`。**判断标准：这个词会跟着图形动吗？会就用 `label`。**

示例（一个框带字 + 一根绑到它的箭头）：

```json
[
  { "id": "reg-start", "t": "ellipse", "x": 435.5, "y": 171, "w": 180, "h": 66,
    "s": "#c2410c", "bg": "#fed7aa", "clean": true, "label": "开始" },
  { "id": "reg-phone", "t": "rectangle", "x": 425.5, "y": 330, "w": 200, "h": 66,
    "s": "#1e40af", "bg": "#dbeafe", "clean": true, "label": "输入手机号" },
  { "id": "ar-1", "t": "arrow", "from": "reg-start", "to": "reg-phone" }
]
```

判定分支长这样——「是」写在箭头上，不是一个孤零零的 text：

```json
[
  { "id": "reg-valid", "t": "diamond", "x": 445.5, "y": 480, "w": 160, "h": 110,
    "s": "#854d0e", "bg": "#fef9c3", "clean": true, "label": "格式正确？" },
  { "id": "reg-code", "t": "rectangle", "x": 425.5, "y": 680, "w": 200, "h": 66,
    "s": "#1e40af", "bg": "#dbeafe", "clean": true, "label": "输入验证码" },
  { "id": "reg-bad", "t": "rectangle", "x": 140, "y": 505, "w": 180, "h": 60,
    "s": "#991b1b", "bg": "#fee2e2", "clean": true, "label": "格式错误" },
  { "id": "ar-yes", "t": "arrow", "from": "reg-valid", "to": "reg-code", "label": "是" },
  { "id": "ar-no", "t": "arrow", "from": "reg-valid", "to": "reg-bad", "label": "否", "s": "#991b1b" }
]
```

用了 `from`/`to` 就不用再写 `pts` 和坐标——后端自己算并绑定。
如果只给一端（例如箭头从框出发指向画布外），只写 `from` 或只写 `to`。
两端都自由飘的线用 `pts`，形如 `{"id":"l1","t":"line","x":0,"y":0,"w":0,"h":0,"pts":[[0,0],[60,40]]}`。

后端会拒绝重复 id、拒绝首点不为 `[0,0]` 的连线。**写错了先看报错再重写，不要原样重发。**

## 三条硬约定

**一、`id` 必须稳定且唯一。** 改已有元素时沿用原 id，新元素才起新 id。重复 id 会被拒绝。

**二、沿用 id 就能保住笔迹与绑定。** 后端为同 id 的旧元素完整保留它的 `seed`、图层顺序、箭头绑定和框内文字——这正是"像同一支笔"的技术实现。反过来说，**别自己造 seed**，紧凑格式里也没这个字段。

**三、先读再写。** 任何修改都从 `board_get` 开始。

**四、分支上的「是」「否」用箭头的 `label`，不要用独立 text。** 游离的文字看起来对，但它只是一串坐标——用户一拖框，它就留在原地，对着一条已经跑掉的线。这是最常见的坏图。

**六、形状加 `label`，箭头用 `from`/`to`。** 这样用户拖动节点时箭头跟随、双击形状能改字。手写坐标的箭头和漂浮的文字不会有这些能力。

## 优先用 Mermaid，别手算坐标

画**流程图、时序图、类图、状态图、ER 图、甘特图、思维导图**这类有固定结构的图时，用 `board_draw_mermaid`，把图写成 Mermaid 文本就行：

```
flowchart TD
  A[开始] --> B{格式正确?}
  B -->|是| C[输入验证码]
  B -->|否| D[格式错误]
```

为什么优先它：Mermaid 自己排版，间距、连线走向、箭头吸附、标签绑定都是对的；手写 `board_write` 的坐标得你自己算，算得再仔细也容易让箭头飘在框外。

几点要注意的：

- **默认会新建一个画板文件**，不会动用户已有的任何文件。给它一个 `title`（如"用户注册流程"），那就是新文件的名字——你比语法更清楚这张图在讲什么，别省这一步。
- **只有用户明确点名要改某个画板时**（"改一下 xx"、"加到 xx 里"），才传 `boardId` 写进那个已有画板；此时 `mode` 才有效（`append` 接在下方，`replace` 清空）。**不要**为了让图"看起来干净"就传 `replace`——那会删掉用户的东西。
- **转换在浏览器里做，所以必须先打开白板卡片**。卡片没开就会等不到回应。
- 写完之后如果需要调整，用 `board_get` 读回来——那时拿到的就是普通图元，可以继续用 `board_write` 改。
- 图元 id 由 Mermaid 生成，不是你指定的 id。

只有“随手画几个框、连几根线”这种两三个元素的小图，才直接 `board_write`——Mermaid 的语法开销反而不划算。

## 画完之后自检

你画的时候是看不见图的。两个工具分别补上一半，**建议画完就跑一遍**：

**`board_check`——结构对不对。** 纯静态检查，**不需要打开白板卡片**。它查的是数据层面的事实：箭头两端是否真的吸在图形上（双向登记）、标签是否真的绑在容器里、绑定有没有指向不存在的元素、箭头的 `points` 首点是否为 `[0,0]`。

它的输出分两档：**错误**（结构真的断了，图是错的）与**可疑**（可能是笔误，你自己判断）。只看“错误”是否为零即可。

`board_write` 每次写完会**自带一次检查**，有问题会直接写在返回里；`board_check` 是想单独细看、或别人改过之后复查时用。

**`board_render`——好不好看。** 把画板渲染成 PNG 并返回**文件路径**，你用普通读文件的工具把那张图读进来，就真的看到了。挤不挤、文字有没有被裁、排版读不读得顺，只有看图能判断，`board_check` 数不出来。

- **这一步必须由页面完成**（后端没有画布）：要问一个开着的页面要画布，所以一个页面都没开才会失败。
- **能渲染哪些板，取决于哪种页面开着**——白板页面**只持有它当前打开的那一块**，要渲染别的板得先 `board_share` 给那块板开一张预览卡；**预览卡能读任意板**。
- 因此想自己闭环、不打断用户：**先 `board_share` 开一张预览卡，再 `board_render`**，不用让用户切画板。
- 省略 `boardId` = 白板上当前打开的那张，拿到的是**实时画布**（`live`）；指定了别的板则读保存的文件（`disk`），结果会告诉你来源——`disk` 意味着可能不含尚未保存的手绘改动。
- 一次往返比 `board_get` 贵得多（要渲染 + 落盘 + 你读图），**画完确认一次就好**，不要每笔都跑。

典型顺序：`board_draw_mermaid` → `board_check`（便宜，先确认结构）→ `board_render`（贵，看一眼）→ 不满意就改。

## 设计系统

### 配色（语义固定，不要自创）

| 用途 | 填充 | 描边 |
| --- | --- | --- |
| 入口 / 主流程 | `#dbeafe` | `#1e40af` |
| 数据 / 成功 | `#dcfce7` | `#166534` |
| 判断 / 条件 | `#fef9c3` | `#854d0e` |
| 错误 / 关键路径 | `#fee2e2` | `#991b1b` |
| 外部服务 / 存储 | `#f3e8ff` | `#6b21a8` |
| 常规处理步骤 | `#e0f2fe` | `#0369a1` |
| 起点 / 触发 | `#fed7aa` | `#c2410c` |
| 分组 / 泳道底 | `#f1f5f9` | `#475569` |

文字：标题 `#1e293b`，标签 `#334155`，辅助说明 `#64748b`。

遵循 **60-30-10**：60% 留白，30% 主色，10% 高亮色。

### 字号层级

标题 28 · 分组标题 24 · 节点标签 20 · 补充说明 16 · 批注 14

### 容器克制

**不要给每个标签都套一个框。** 默认用独立的 `text` 元素，框只留给真正的组件、起止节点、判断菱形、或者圈出一块区域。目标是文字元素里套框的不超过 30%。

### 尺寸与间距

形状宽度按标签文字长度推算：拉丁字符 `max(160, 字符数 × 9)`，中文 `max(160, 字符数 × 18)`，再加 20px 内边距。

- 带文字的连线间距：150–200
- 无文字的连线间距：100–120
- 同列元素垂直间距：100

坐标用 `.5` 结尾像素对齐，视觉上更锐利。

### 连线语义

- 实线 = 主流程
- `dash: "dashed"` = 返回 / 异步 / 回调 / 回环
- 弱依赖用 `dash: "dotted"`

箭头两端会自动吸附到绑定元素的边缘，**但你要把它们放得够远**——中间至少留 100 的空隙，箭头才有东西可画。元素挨在一起时绑定箭头会显得很挤。

### 图式选择

| 关系 | 画法 |
| --- | --- |
| 一对多（广播 / 分发） | 扇出：一个节点，多条箭头 |
| 多对一（聚合 / 合并） | 汇聚：多条汇入一个 |
| 层级（父子） | 树：主干 + 分支 + 自由浮动文字，**不要用一串矩形** |
| 循环 / 反馈 | 环：节点排成圆，箭头绕回起点 |
| 多步处理 | 流水线：从左到右排开 |
| A 与 B 对比 | 并排两列，共用基线 |
| 阶段划分 | 留白或一条虚线分隔，不要画满框 |
| 边界不清的状态 | 云朵状椭圆重叠 |

时间轴就是一条基线加几个点；层级就是线和文字。**结构本身在表达含义，填充色块留给真正的组件。**

## 删元素

从 `elements` 列表里移除即可，不要留 `isDeleted` 标记。

## 常见错误

- 没 `board_get` 就写 → 抹掉用户的画
- 同一个 id 出现两次 → 被拒绝
- 分支的「是」「否」用独立 text 而不是箭头的 `label` → 用户一拖框，字就留在原地
- 给每个框配一个独立 text 而不是用 `label` → 拖框时字不跟着走
- 用手写坐标的箭头而不是 `from`/`to` → 拖节点时箭头不跟随
- 忘了带原有元素 → 用户的东西全没了
- 元素超出一屏 → 用户第一眼看不到。以 `(0,0)` 为起点向右下展开，整体控制在 1600×1500 内
- 一次画太多 → 20–40 个图元是合适的；更多先和用户确认要不要拆成多张板
